## Skill 系统设计讨论

### 时间
2026/06/24

### 核心诉求
用户希望 xl_ai 能兼容市面上大多数的 skill，做到"找到即用，零手动适配"。

### 市面主流 Skill 安装方式
1. **MCP 方式** — 配置声明式，有 `list_tools()` 标准化接口，能自动发现工具详情
2. **CLI 方式** — 命令调用式，缺乏自描述能力，需要 `--help` 或配套描述文件
3. **Skill 手册** — .md 文件，纯文本说明书，按需加载

### 核心痛点
CLI 工具装完后不知道装在哪，没有类似 MCP 那样的 `list_tools` 自动发现能力，如果走 CLI 路线需要手动适配。

### 自动加载方案思路
xl_ai 启动时自动扫描 `skills/` 目录：
- **MCP 类型** → 自动读取配置，拉起进程，调用 `list_tools()` 获取工具详情
- **CLI 类型** → 自动跑 `--help` 解析，或读取配套描述文件
- **Skill 手册** → 加载简介到上下文，按需展开

### 用户倾向
用户希望找到一个 skill 后只需放到目录下就能用，不需要手动改配置或写适配代码。
